# trip-archive — 团后归档器

> 原为独立技能，现作为 `travel-workflow` 管线的参考文档。脚本已移至 `scripts/trip_archive.py`。

## 执行

```bash
python3 scripts/trip_archive.py <trip_json_path>
```

## 归档映射

脚本通过两级匹配识别缓存文件：

### 1. 英文前缀匹配（优先）

| 文件前缀 | → 文档类型 | → 知识库节点 |
|---------|-----------|------------|
| `quote_*` | 报价单 | 02-销售转化 |
| `briefing_*` | 出团通知书 | 03-出团执行 |
| `guide_exec_*` | 导游执行单 | 03-出团执行 |
| `supply_check_*` | 物资核对 | 03-出团执行 |
| `vendor_hotel_*` | 酒店对接 | 04-供应商对接 |
| `vendor_transport_*` | 车辆对接 | 04-供应商对接 |
| `vendor_guide_*` | 地接对接 | 04-供应商对接 |
| `cost_*` | 成本核算 | 01-产品研发 |
| `route_*` | 路线方案 | 01-产品研发 |

### 2. 中文关键词匹配（回退）

当文件名不含上述英文前缀时，回退到在文件名中搜索中文文档类型名（如"导游执行单"出现在 `guide_exec_导游执行单_xxx.md` 中也会命中）。

### 去重规则

同一文档类型的 `.html` 和 `.pdf` 同时存在时，仅保留 `.pdf`。

## 输出

- 飞书 docx 归档报告 → 05-归档结算
- 本地缓存：`~/.hermes-feishu/cache/archive_<团号>.md`

## 陷阱

- **文件命名必须遵守前缀约定**：`quote_`、`briefing_`、`guide_exec_` 等前缀是匹配的关键。如果新脚本产出的文件名不遵循此约定，归档器将无法识别，只能靠中文回退碰运气。
- **归档报告不可重复跑**：每次执行都会在飞书知识库创建新文档。如需更新已归档的报告，应手动删除旧文档后重新执行。
