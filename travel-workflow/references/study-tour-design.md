# study-tour-design — 研学/定制方案设计

> 非标准旅行产品（研学、夏令营、企业定制）的设计工作流。不经过 `trip.json` 管线，输出为独立的对客飞书文档。

## 与标准管线的区别

| 维度 | 标准旅行（trip.json 管线） | 定制方案（本参考） |
|------|--------------------------|-------------------|
| 输入 | 活动价目表 + 客户需求 | 机构需求描述（主题/年龄/天数/人数） |
| 流程 | trip.json → 8 技能全链路 | 5 阶段结构化设计 |
| 输出 | PDF 报价单 + docx 执行单 | 单一对客飞书文档（含行程+报价） |
| 定价 | 成本核算 → 加价 → 对外报价 | 市场参考区间（标注浮动因素） |
| 产品 | 成熟产品（桨板/探洞/速降） | 定制方案（可能包含非自有资源） |

## 5 阶段工作流

### Phase 1 — Clarify（需求澄清）

通过结构化追问锁定核心决策。典型问题：

- 研学主题方向（自然/文化/非遗/户外/综合？）
- 出行时间/季节（影响活动可行性和报价）
- 年龄范围 + 人数（决定活动难度和安全设计）
- 必含活动（如"桨板一天 + 洞穴一天"）
- 住宿标准、集散地、预算上限

**产出**：决策树 + 关键决策摘要 + 开放追问列表

### Phase 2 — Brief（结构化简报）

将需求转化为设计约束。内容包括：

- 问题定义（一句话说清这个方案要解决什么）
- 目标方案（方案形式、读者、阅读体验目标）
- 核心原则（3-5 条不可妥协的设计准则）
- 领域约束（区域/人数/时间/预算/必含项/合规要求）
- 成功标准（可验证的完成标准，每条含验证方法）
- 已有资产（可复用的基地/路线/运营经验）
- 产出物清单（类型 + 接收方）
- 不做什么（明确排除项，防止 scope creep）

**产出**：飞书工作流全记录文档（供后续 Phase 追溯决策）

### Phase 3 — Architect（行程骨架）

设计每日主题 + 模块划分，不展开细节。判断标准：

- 难度曲线：D1 适应 → D2-3 轻度 → D4-5 高强度 → D6 缓冲 → D7 收尾
- 每天主题独立，任一天因天气取消不影响整体
- 高风险日安排在相邻日（共用装备运输/专业教练）
- 暑假适配：水上活动午后安排、星空观测晚间安排
- 每天一件"作品"（4-12 岁研学核心：家长能看到的东西）

**产出**：每日主题 + 场所 + 核心活动 + 作品产出 + 安全等级的矩阵表

### Phase 4 — Design（详细行程）

逐日展开：时间线（时刻→环节→内容→时长）、学习目标、安全措施（按常规/中度/高风险分层）、物料准备。

**研学特有设计要点**：
- 年龄分层：高风险活动按年龄段分组（如桨板 8 岁以下不站立、探洞 6 岁以下不走深入段）
- 备用方案：每个户外日给出雨天/恶劣天气替代方案
- 每天下午安排"消化时间"（标本制作/笔记整理），避免全天赶场
- 晚间活动不超 1.5 小时，低龄儿童 21:00 熄灯

**产出**：每日完整时间线（可独立发给家长的格式）

### Phase 5 — Build（正式文档生成）

汇总为单一对客飞书方案文档。结构：

1. 方案概览表（主题/时长/年龄/人数/季节/区域）
2. 为什么选这个方案（1-2 句价值主张）
3. 每日作品一览表（家长感知价值锚点）
4. 每日详细行程（时间线格式）
5. 费用明细（按类别：住宿/餐饮/交通/门票/活动/保险/师资/物料）
6. 费用不含 + 参考总价（分档位，标注浮动因素）
7. 人员配置建议
8. 方案亮点总结

**定价规则**：
- 非自有产品时，给市场参考区间（不编造具体价格）
- 标注浮动因素（季节/人数/实际资源确认情况）
- 加上"最终报价以合同为准"的免责声明
- 分档位给参考（如经济型/舒适型），让机构有选择空间

### 文档创建命令

```bash
cd /tmp
lark-cli docs +create --api-version v2 --doc-format markdown \
  --content @方案文件.md --parent-token <wiki_node_token> --as bot
```

## 与 zhike-content-output 的衔接

定制方案本质是对客文档，需遵守 `zhike-content-output` 的产品铁律：
- 不编造不存在的产品细节（水深/洞穴结构/设施数据）
- 不确定的价格标注"参考"和"浮动因素"
- 不在对客文档中出现内部方法论术语

## 与 route-designer 的关系

`route-designer` 适用于已有完整活动价目表的行程编排（标准旅行产品）；本参考适用于从头设计的定制方案（研学/夏令营/企业定制）。两者在行程编排逻辑上相通，但输入源和产出格式不同。
