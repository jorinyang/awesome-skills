# Phase 4 Standards 变体：内部制度文档 / 财务分润文档

> 触发条件：用户说"非财务人员也要看懂""用叙述性语言""手机计算器要能算""不要代码块"。
> 本变体替代通用 Standards 模板中的命名约定和格式规范。

## 背景

用户（杨瑒）在设计企业管理培训分润体系时，Phase 4 Standards 初稿使用了代码块公式和单字母变量（α/C/D/d）。用户纠正："确保这个标准规范是可以（1）用公式实现的、（2）简单易懂的、（3）非财务人员也能理解的、（4）可以被叙述性语言完整描述的。"

此反馈催生了本变体。原则适配：内部制度文档的受众不是工程师，而是财务、项目经理、甚至外部合作的讲师。

## 铁律

**铁律一：每个公式都能用手机计算器按出来。**
不允许"分段函数需要编程实现"这类表述。资金占用费的递减公式写成：`费率 = 50% ×（1 − 已等天数 ÷ 结算周期）`——任何一个项目助理拿手机计算器都能算。

**铁律二：每个公式旁边都有一句人话解释。**
格式固定为："这一步在算什么？→ 公式 → 为什么这样算"。文本顺序不可颠倒。

## 命名约定（覆盖通用模板）

废除单字母变量，改用中文全称。公式中保留中文变量名：

| 变量 | 含义 | 格式 |
|------|------|------|
| 合同总额 | 客户签的含税总价 | 中文全称 |
| 业务机会费率 | 渠道佣金比例 | 中文全称 + % |
| 讲师分润比 | 该层级讲师从利润中分走的比例 | 中文全称 + % |
| 已等天数 | 从授课日到实际结算日已过去的天数 | 中文全称 |

税率保留 T1/T2/T3 符号（因为需要在不同场景间快速指代），但每个首次出现处标注全称。

## 格式规范（覆盖通用模板）

| 项目 | 规范 | 理由 |
|------|------|------|
| 金额 | ¥12,345.67（千分位+两位小数） | 财务通用格式 |
| 百分比 | 15% 或 15.0% | 不出现 0.15 这种小数写法，避免混淆 |
| 公式 | **用自然语言写，不用代码块** | 例："业务机会费 = 合同总额 × 业务机会费率" |
| 计算步骤 | 每步三行：干什么 → 怎么算 → 算出来是多少 | 读完即可验算 |

## 复用模式

### 计算步骤块（全文统一）

```markdown
### 第 N 步：{步骤名称}

**在算什么**：{一句话}

**公式**：{中文变量名，不用代码块}

**为什么**：{一句说清逻辑}

**本例**：¥XXX = ¥XXX × XX% = ¥XXX
```

九个步骤用同样格式，读者学会一个就全会了。

## 反模式（追加到通用模板）

| # | 反模式 | 正确做法 |
|---|--------|------|
| 1 | 用代码块写公式 | 用自然语言，变量用中文全称 |
| 2 | 在示例里只给最终数字不给中间步骤 | 每一步都写出中间值 |
| 3 | "约等于""大概是"等模糊词出现在数字前 | 精确到分；舍入规则显式声明 |
| 4 | 用表格代替叙述性说明 | 表格后面必须跟一句人话解释 |
| 5 | 财税术语不加解释 | 首次出现的专用词附一行白话释义 |

## 验证信号

当 Phase 4 产出被用户认可时，典型信号：
- "可以，请继续" / "基本没问题" → Standards 方向正确
- "非财务人员也能理解" → 铁律二已生效
- 用户在 Build 阶段没有纠正公式可读性 → 反模式已全部规避
