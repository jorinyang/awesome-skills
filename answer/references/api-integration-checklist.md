# API 集成对接清单模板

> 用于 answer 工作流中需要与外部系统定义接口的场景。适用于票务系统、支付系统、ERP 对接等任何需要明确双方接口契约的项目。

## 模板结构

每个接口定义包含六个部分：

### 1. 接口元信息

| 项目 | 内容 |
|------|------|
| 方向 | 数据流向（A → B） |
| 方式 | HTTP POST / GET / WebSocket |
| URL | 完整端点地址 |
| 鉴权 | API Key / Token / IP白名单 |

### 2. 请求字段表

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|

- 字段名用 snake_case
- 类型明确（string / int / decimal / boolean / array）
- 必填标记用 ✅ 或 "选填"

### 3. 响应格式

```json
{ "success": true, "data": {...} }
{ "success": false, "error": { "code": "ERR_CODE", "message": "描述" } }
```

### 4. 幂等设计

- 明确幂等键
- 说明重复调用的行为
- 如不可幂等，标注为人工兜底

### 5. 调用时机

- 触发条件
- 期望延迟（如 < 30秒）
- 失败重试策略

### 6. 对接前置要求

以表格列出对方需在截止日前提供的资源（文档 / 测试环境 / 对接人）。

## 真实案例

参考本项目的 `峰林文旅体-票务系统/05_小桔子接口对接清单.md`，包含：
- 接口1：订单推送（Webhook 回调）
- 接口2：核销回传（幂等）
- 接口3：订单查询（兜底拉取）
- 接口4：退款通知（理想态，非必须）
- 6项对接前置要求 + 截止日

## 常见陷阱

| # | 陷阱 | 正确做法 |
|---|------|---------|
| 1 | 只定义正向接口，无兜底 | 每个关键接口需配兜底方案（轮询/人工） |
| 2 | 未定义幂等键 | 每条接口必须明确：用什么字段防重、重复调用的行为 |
| 3 | 无截止日 | 前置要求每条标注截止日，否则永远"待确认" |
| 4 | 只写给技术看 | 接口清单中也包含"需要老板拍板"的决策项（如费率、结算周期） |
