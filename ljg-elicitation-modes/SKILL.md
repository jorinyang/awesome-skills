# advanced-elicitation 模式扩展

本技能为 `advanced-elicitation` 新增三种审视模式，应在 advanced-elicitation 被加载时同时加载。

## 模式 #70：八维概念解剖

**吸收自 ljg-learn**

### 触发
- 用户说"解剖这个概念/概念解剖/explain concept/learn concept"
- 用户给出一个概念并要求深度理解（非定义查询）
- advanced-elicitation 的判断逻辑：内容类型 = 概念/术语 → 优先推荐此模式

### 流程

**Step 1: 定锚**
- 这个概念最通行的定义是什么？常见误解在哪？
- 概念里藏着哪几个核心词素？

**Step 2: 八刀** — 八个方向各切一刀，每刀 2-3 句，只留筋骨

1. **历史**：最早从哪冒出来 → 怎么变的 → 哪一步拐成了今天的意思
2. **辩证**：它的反面是什么 → 正反碰撞后，更高一层的理解是什么
3. **现象**：扔掉所有预设，回到事情本身 → 用一个日常场景把它还原出来
4. **语言**：拆字源（中/英/希腊/拉丁）→ 画出相邻概念的语义网 → 这个词暗含什么隐喻
5. **形式**：写一个公式或形式化表达 → 公式在哪里失效
6. **存在**：这个概念改变了人怎么活着
7. **美感**：它美在哪？用一个具体意象呈现
8. **元反思**：我们在用什么隐喻理解它？这个隐喻挡住了什么？换一个会怎样

**Step 3: 内观**
- 变成这个概念本身，用第一人称看世界。3-5 句
- 八刀之中，哪几刀指向同一个深层结构？提出来

**Step 4: 压缩**
- 公式：`概念 = ...`
- 一句话：用最简单的话说出最深的理解
- 结构图：SVG 架构图（白底黑字+蓝标注+红强调，16:9）

## 模式 #71：结构化圆桌讨论

**吸收自 ljg-roundtable**

### 触发
- 用户说"圆桌讨论/圆桌/roundtable/辩论"
- 用户想探索一个议题的多视角辩证分析
- advanced-elicitation 的判断逻辑：内容类型 = 争议性议题/哲学问题/战略分歧 → 优先推荐此模式

### 流程

**Step 1: 解析议题** — 从用户输入提取核心议题

**Step 2: 选人** — 选择 3-5 位真实历史/当代人物，覆盖多元立场
- 每位人物：姓名 + 核心立场 + 选择理由
- 至少一位"意外视角"——来自议题领域之外的人
- 选人原则：立场必须形成张力网络（非简单正反方）

**Step 3: 开场** — 主持人开场，展示参会人物，提出定义性问题：
> 「在深入探讨之前，我们应当如何定义 [议题核心概念]？」

**Step 4: 多轮辩证** — 每轮聚焦最深的争议点
- 每位人物依次发言：`【人物名】【行动标签】：发言内容`
- 主持人引导方向，不表态
- 每轮生成一张思考框架图（矩阵/光谱/因果环路/层级树）

**Step 5: 收尾**
- 知识网络：各人物核心观点的关联图
- 主持人总结分歧的本质（不判断谁对谁错）
- 开放问题列表

## 模式 #72：降秩审视

**吸收自 ljg-rank，作为 domain-decompose 的轻量审视版**

### 触发
- 方案/策略审查中发现过度设计
- 用户问"这个方案的核心约束是什么/哪些是可以砍的"
- advanced-elicitation 的判断逻辑：density 高 + 需要精简 → 推荐此模式

### 流程

**Step 1: 铺开** — 列出当前方案/系统的所有要素（不加筛选）

**Step 2: 砍** — 逐一问：拿掉这个，剩下的还能工作吗？
- 能 → 砍掉（这是伪约束）
- 不能 → 保留（这是真约束）

**Step 3: 反生成** — 用保留的要素，能不能把系统的全部功能倒回来？
- 不能 → 还缺一根，回去找

**Step 4: 输出** — 一句话："这个方案说到底就是 {N} 根线在撑着"
- 配 SVG 取景框图

### 自动伴随加载（与 advanced-elicitation 同时加载）

当 advanced-elicitation 被触发时，本技能的3种模式自动纳入候选池：

| advanced-elicitation 触发场景 | 自动路由到的模式 |
|------------------------------|----------------|
| 内容类型 = 概念/术语 | 方法列表中包含 #70 八维概念解剖 |
| 内容类型 = 争议性议题/哲学问题/战略分歧 | 方法列表中包含 #71 结构化圆桌讨论 |
| 内容类型 = 方案/策略且元素数 > 10 | 方法列表中包含 #72 降秩审视 |

### 手动触发关键词
解剖概念、概念解剖、explain concept、八维解剖、圆桌讨论、圆桌、roundtable、辩论、多视角、降秩审视、精简方案、砍需求、过度设计

### 不触发
- 简单定义查询（"什么是XX"→直接回答，不需要八维解剖）
- 已有明确答案的非争议性问题（"1+1等于几"→不需要圆桌）
- 元素少（<5个）的方案 → 不需要降秩审视
