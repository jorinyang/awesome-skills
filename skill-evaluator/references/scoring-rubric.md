# 六维打分细则

## 1. 目的适配性 (1-5分)

评估 Skill 是否具有清晰的单一目的，并能让 LLM 准确识别调用时机。

| 分数 | 标准 |
|:---:|------|
| 5 | 聚焦单一目的，触发信号清晰；LLM 可准确判断调用时机 |
| 4 | 有明确主目标，触发条件基本可行，偶有歧义 |
| 3 | 有主要目标但耦合可拆分职责；触发条件抽象 |
| 2 | 跨多个弱相关问题域；description 缺触发条件 |
| 1 | 跨多个不相关任务；description 完全缺失触发条件 |

## 2. 结构规范性 (1-5分)

评估元数据内容质量和信息密度。不重复 L1 的格式检查。

| 分数 | 标准 |
|:---:|------|
| 5 | description 表达规范、SKILL.md 高度精炼、外置链接完整 |
| 4 | 内容精炼，少量可优化的冗余 |
| 3 | 基本规范，含少量可拆分背景说明或非核心代码块 |
| 2 | 内容堆砌，多处可外置的长代码/配置块 |
| 1 | 长内容堆砌单文件、解释通用概念、缺少分级加载 |

## 3. 指令适配性 (1-5分)

评估指令自由度是否与任务的风险等级匹配。

| 分数 | 标准 |
|:---:|------|
| 5 | 自由度与任务风险完全匹配 |
| 4 | 基本匹配，极少数场景自由度偏高 |
| 3 | 基本匹配，少量场景过严或过松 |
| 2 | 明显错配，如中风险操作给高自由度 |
| 1 | 严重错配，如高风险操作让 LLM 自由判断 |

## 4. 内容一致性 (1-5分)

评估术语、表达风格是否一致。

| 分数 | 标准 |
|:---:|------|
| 5 | 术语统一、风格一致、无硬编码时效信息 |
| 4 | 术语基本统一，偶有混用但可理解 |
| 3 | 可理解但少量术语混用 |
| 2 | 多处术语混用、表达风格跳跃 |
| 1 | 术语混乱、表达矛盾、明显硬编码 |

## 5. 工程健壮性 (1-5分)

评估脚本质量和错误处理。

| 分数 | 标准 |
|:---:|------|
| 5 | 所有脚本有错误处理、幂等运行、前置校验完整 |
| 4 | 核心脚本有基础错误处理，大部分幂等 |
| 3 | 有基本错误处理，缺少边界情况覆盖 |
| 2 | 错误处理不完整，缺少关键前置校验 |
| 1 | 脚本无错误处理，无幂等保证，无前置校验 |

## 6. 安全风险性 (1-5分)

评估是否包含不安全操作模式。

| 分数 | 标准 |
|:---:|------|
| 5 | 无安全风险，所有敏感操作有明确安全约束 |
| 4 | 极低风险，有基本安全约束 |
| 3 | 存在低风险操作但影响可控 |
| 2 | 存在中风险操作缺少安全约束 |
| 1 | 包含高危操作（rm -rf、DROP TABLE 等）且无安全指引 |

## 三维执行评分

### 执行精准度 (Effectiveness)

| 分数 | 标准 |
|:---:|------|
| 5 | 所有步骤 ✅，结果正确，无多余操作 |
| 4 | 1-2 个 ⚠️，结果正确 |
| 3 | 3+ 个 ⚠️ 或 1 个 ❌，结果基本正确 |
| 2 | 多个 ❌，结果部分正确 |
| 1 | 大量 ❌ 或 ⭕，结果错误 |

### 端到端时效 (Efficiency)

| 分数 | 标准 |
|:---:|------|
| 5 | 总耗时在同类任务 P25 以内 |
| 4 | 总耗时在同类任务 P25-P50 |
| 3 | 总耗时在同类任务 P50-P75 |
| 2 | 总耗时在同类任务 P75-P90 |
| 1 | 总耗时在同类任务 P90 以上，或明显超时 |

### 计算成本 (Token Cost)

| 分数 | 标准 |
|:---:|------|
| 5 | Token 消耗在同类任务 P25 以内 |
| 4 | Token 消耗在同类任务 P25-P50 |
| 3 | Token 消耗在同类任务 P50-P75 |
| 2 | Token 消耗在同类任务 P75-P90 |
| 1 | Token 消耗在同类任务 P90 以上，或出现浪费式重复调用 |
