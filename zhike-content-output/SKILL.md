# 贵州之客内容产出准则

## 核心区分：工具 vs 产物

> ⚠️ **这是贵州之客内容产出的第一核心原则，优先级高于一切写作技巧。**

| 概念 | 定义 | 出现位置 |
|------|------|---------|
| **价值观**：山河五则 | 思想指引/意识形态 | 仅用于内部推理和判断，**不出现**在输出文档中 |
| **方法论**：体验式工作法 | 行为动作的实施路径 | 仅用于内部推理和判断，**不出现**在输出文档中 |
| **输出文档** | 用户需求的结果性内容 | 纯净的结果，不含上述工具的原文或关键词 |

## 推理过程（内部，不输出）

当收到一个内容需求时：

1. **用价值观做 filter** — 这个设计/方案是否符合山河五则？哪几条在起作用？
2. **用方法论做路径** — 这个需求应该用「编剧·制片·主演」还是「破冰·沉浸·余响」来推导？
3. **输出结果** — 文档中只写结果：产品方案、SOP、时间表、定价表、话术文本

**推理过程不需要显式呈现。** 用户看到的是他们要的结果，不是你的推导过程。

## 错误示例

❌ **错误：把方法论文本写进产品文案**

```
产品设计理念：
采用「编剧·制片·主演」的方法论...
序曲→铺垫→高潮→尾声的情绪动线设计...
```

❌ **错误：在结果文档中复述价值观条目**

```
本产品体现了「山不让土，故能成其高」的开放连接精神...
```

✅ **正确：只输出结果性内容**

```
产品结构：Day1 晚风轻徒步（松弛入戏）→ Day2 上午 犀牛洞探险（核心高潮）→ Day2 下午 天坑绳索（突破瞬间）→ Day3 慢民宿+篝火（余响留存）
```

## 什么时候才需要在文档中写价值观/方法论？

**只有一种情况：** 用户明确要求「体现山河五则」或「用方法论包装」——这是特定的内容包装需求，不是默认行为。

默认行为 = 工具内化，结果外显。

## Feishu 输出格式规则

- **简单输出**（≤3点，纯文字）→ 直接发 Feishu 卡片，用纯文本
- **复杂输出**（含表格/多级标题/结构化内容）→ 创建 Feishu 在线文档，输出文档链接
- **禁止**：在卡片消息中用 Markdown 表格 `| |`、标题 `##`、引用 `>` — Feishu 不支持，会渲染为原始标签

> ⚠️ **飞书在线文档 API 约束**：实测支持 block_type 2/3/4/5/12/13/15/22（text、heading1~3、bullet、ordered、quote、divider）。表格/代码块等不支持，需降级处理。详见 `feishu-doc` 技能的 block_type 对照表。

## 对客写作

对客写作铁律（禁令/标准/必含元素）→ `references/client-facing-writing.md`

**触发条件**：任何面向客户的文案（企业简介、产品介绍、宣传页、公众号推文），自动加载此参考文件。

### 品牌简介写作（2026-06-01 新增）

**公司简介的定位**：告诉别人你是谁、你做什么、为什么选你。不展开，不铺陈，不叙事。

| ✅ 简介该做的 | ❌ 简介不该做的 |
|-------------|-------------|
| 一句话说清你是谁 | 大段场景描写和故事叙事 |
| 三块基地各一句话 | 像公众号推文一样展开每个产品 |
| "为什么选我们"用选择标准来答 | 把教练写成全篇灵魂——灵魂是品牌和基地 |
| 安全保障一段收掉 | 罗列卖点 |
| 证言2-3条快速过 | 长篇客户故事 |
| 结尾干净利落 | "欢迎咨询""专属定制"等万能结尾 |

**铁律**：简介的灵魂是基地和品牌选择标准，不是教练。教练是执行者，在安全保障段出现即可。

### 冷启动脚本铁律（2026-06-01 新增，2026-06-04 修订）

抖音/视频号/小红书冷启动期，每条脚本发布包**必须**包含以下全部元素，缺一不可：

1. **前3秒钩子**（画面+声音+信息悬念，三秒内不建立观看理由=脚本回炉）
2. **文案**（发布时写的标题文字）
3. **标签**（三层：身份标签→内容标签→人群标签，8个固定）
4. **评论引导**（合并为1条，发完立刻自己写。两条抢赞、两条观众只回一条——合并为一个互动钩子+一个可回应的切口）
5. **封面字**（视频封面上叠什么字）

> ⚠️ 标签和钩子最容易在细化脚本时遗漏——因为注意力集中在分镜和文案上。每次交付脚本方案前，对照清单检查每条是否五元素齐全。

### 冷启动完整交付物（2026-06-04 新增）

当用户提交冷启动脚本方案并要求入库时，**同步产出两份文档**：

1. **原始方案入库** — 完整保留脚本分镜表、拍摄规划、发布节奏、执行清单，归档至知识库运营策略分类
2. **评论回复手册** — 基于脚本内容预判客户可能提出的问题，按品牌叙事声音撰写逐条回复示例

回复手册结构参考 `references/comment-reply-guide-structure.md`，核心要求：
- 每类问题（安全/预约/能力/装备/交通/天气）给出完整回复示例，非模板式答案
- 按14条脚本逐条预判评论类型和高概率问题，给出针对性话术
- 覆盖评论类型策略（赞美/@朋友/质疑/对比/本地人/铁粉）
- 平台差异化（抖音快节奏反问、视频号偏正式可转发、小红书攻略向长回复）
- 回复铁律：不是客服腔（禁用"亲""宝""欢迎光临"），是真人回朋友；前30分钟必回所有评论

## 产品/基地文档写作铁律（2026-06-08 新增）

> ⚠️ **触发条件**：任何涉及贵州之客自有基地、产品、路线、设施的具体描述时，本规则优先级最高。

### 禁止发明细节

写产品手册、基地简介、活动方案时，**绝不凭空填补数据空白**。以下条目必须基于用户明确提供的信息，没有就留白或标注"待补充"：

| 类型 | ❌ 禁止行为 | ✅ 正确做法 |
|------|-----------|-----------|
| 地理/水文 | 编造水深、流速具体数值、洞穴内部结构 | 写"流速平缓适中"，不写"水深1-2米" |
| 产品特性 | 假设存在某种体验（如"洞穴桨板"） | 白水河没有洞穴桨板——永远不要写 |
| 路线环节 | 添加未经确认的行程段（如"地下暗河段"） | 犀牛洞299路线不含暗河——以用户提供为准 |
| 设施数据 | 估计更衣室容量、装备数量 | 等用户给数据或标注"待补充" |
| 价格构成 | 猜测成本明细 | 用已有成本核算表数据，不超出 |

### 历史教训

- 白水河桨板简介初稿写了"洞穴桨板"——实际不存在，用户纠正
- 犀牛洞行程写了"地下暗河段"——299路线不含，用户纠正
- 方案中写了"水深1-2米"——用户明确说水深无法给具体数据

**核心原则**：产品文档不是创作——是翻译。把用户给的事实翻译成可对外发送的格式。不给的事实不编。

## 叙事声音规范（2026-06-01 新增）

> **适用范围**：所有对客内容——抖音/视频号/小红书/公众号的文案、字幕、旁白、正文。策略文档和方案文档不在此列。

### 核心原则

**不写教程感，写体验感。** 读者不需要被"教"，需要被带进一个场景。

| ✅ 体验叙事 | ❌ 教程叙事 |
|------------|------------|
| "我第一次上板的时候，在岸边站了五分钟。" | "零基础？三步就能上板！" |
| "教练说，先跪上去。跪上去发现——其实挺稳的。" | "第一步：跪姿上板，手撑板面" |
| "后来教练说，反过来划一下试试。" | "桨板转弯教学：反手划水即可" |

### 六大声音特征

1. **第一人称** — "我""我们"，不是"你"。分享经历，不是下达指令。
2. **感官细节** — "水很凉，天很蓝"不是"水质优良"。写看到的、听到的、身体感受到的。
3. **完整句子** — 每个句号让读者喘一口气。不堆砌短促分句。
4. **不用感叹号** — 不用"🔥""💯""绝了""太震撼了"。让场景本身产生冲击力，不靠标点喊出来。
5. **每句值其位置** — 删掉任何可以删掉而意思不变的句子。不水字数。
6. **不给结论，给画面** — 不说"你会觉得很自由"，写"你在屏幕上很小。但那种小不是渺小。"

### 对照改写示例

**抖音发布文案**：

| ❌ 改写前 | ✅ 改写后 |
|----------|----------|
| 「零基础？没玩过水？怕落水？看这个视频你就知道桨板没你想的那么难。」 | 「我第一次上板的时候，在岸边站了五分钟。教练说，先跪上去。跪上去发现——其实挺稳的。站起来那一下腿是抖的。但看远处不看脚下，就不抖了。」 |
| 「学会这三步，你就是水上最靓的仔🔥」 | 「三步之后，你已经在峡谷里了。回头看岸边，好像也没有那么远。」 |
| 「这个地方也太震撼了吧😱」 | 「飞到峡谷正上方的时候，山从两边压过来，水在下面流过去。」 |

**视频号旁白**：

| ❌ | ✅ |
|----|-----|
| 「我们将为您提供最专业的桨板团建体验」 | 「我们把基地建在这里——不是租的，是自己的。」 |
| 「安全保障是我们的第一优先级」 | 「你下水的时候有人帮你检查救生衣。你落水的时候教练已经在过来的路上。」 |

**小红书正文**：

| ❌ | ✅ |
|----|-----|
| 「🏄水质：活水，不腥不浑，水温刚好」 | 「水灌进耳朵里，整个世界安静了两秒。然后救生衣把我托起来。」 |
| 「💯强烈推荐！必去！」 | 「三小时后上岸。腿是软的。但脑子特别清醒。」 |

### 例外场景

以下场景不适用体验叙事，保持功能性语言：
- **纯操作说明**（如"防晒+换洗衣服+手机防水袋，其余基地全有"）
- **费用/时间/地址等事实信息**（如"人均200+，含装备+教练+保险"）
- **CTA**（如"主页可约""私信获取方案"）——保持简洁直接

### 评论回复写作（2026-06-04 新增）

> **适用范围**：抖音/视频号/小红书评论区回复。与发布文案共享叙事声音规范，但有以下适配。

| 维度 | 发布文案 | 评论回复 |
|------|---------|---------|
| 长度 | 3-5句完整段落 | 1-3句即可，一句话能收就收 |
| 人称 | "我"分享经历 | "你"+"我们"——对方在问，你在答 |
| 节奏 | 完整叙事弧 | 快接快回，30分钟内必回 |
| 口吻 | 在讲一个故事 | 在回一个朋友 |
| 目标 | 让人停下来看完 | 让人想接下一句 |

**回复写作铁律**：

1. **必须有称呼** — 绝不不带称呼直接跳入回答。三种情况：昵称可提取的用昵称简写（"爱旅行的小明"→"小明"）；昵称不可提取的用自然开场（"看到你问这个——""你问到点子上了——"）。禁止纯客服腔称呼（"亲""宝""小伙伴"），禁止"您"（产生距离感）
2. **尽量用问句结尾** — 把话递回去，让对话继续。四类问句：拉回场景（"你是第一次玩吗？"）、推进决策（"周末还是工作日？"）、唤起共鸣（"你落水的时候笑了吗？"）、轻互动（"你呢？"）。写完每条回复后检查最后一句——如果是句号结尾的陈述句，问自己能不能加一个问句
3. **不用客服腔** — 禁用"亲""宝""小伙伴""欢迎光临""期待您的光临"，一用就破功
4. **不用万能模板** — 不同问题给不同答案。复制粘贴同一句话回不同人=品牌灾难
5. **不顶嘴不辩护** — 遇到质疑不争辩。用事实轻描淡写，留给其他人判断。负面评论不用问句——会显得挑衅
6. **给画面不给答案** — 问"安全吗"不给"很安全"，给"你下水的时候有人帮你检查救生衣"
7. **评论区不报价** — 具体价格引导私信或主页查看，避免评论区变成价格对比现场

**称呼 + 问句结尾对照示例**：

| ❌ 不带称呼、陈述结尾 | ✅ 带称呼、问句结尾 |
|-------------------|-------------------|
| "白水河大部分水深一米到两米。教练全程在水上。" | "小明，白水河大部分水深一米到两米。教练全程在水上——你是第一次玩还是之前试过？" |
| "可以。很多家长带着孩子来。" | "可以。很多家长带着孩子来。小朋友几岁了？" |
| "谢谢。白水河确实美。" | "你看到的是无人机拍的——但站在水上抬头看峡谷，是另外一种感觉。你更喜欢高空视角还是水面视角？" |

**禁止句式**：
- ❌ "当然可以！" → ✅ "你穿着救生衣，教练就在旁边。"
- ❌ "非常安全！" → ✅ "教练全程在水上。你落水的时候，他过来的距离不超过十秒。"
- ❌ "欢迎来玩！" → ✅ "周末早上出发，十点就在水上了。"

## 标签策略（2026-06-04 新增）

**禁止添加的标签**：
- `#抖加小助手` — 付费推广专用标签，跟内容分发无关
- `#我要上热门` `#上热门` — 2020年以前的玩法，现在对算法权重零影响。加这些标签=自降品质感
- 任何@账号的标签（`@抖音小助手` 等）——算法分发时代无人审核

**标签位优先原则**：每条视频标签位有限（5-10个），每多一个无效标签就少一个有效关键词。宁可少标，不标垃圾。

**固定标签优化**：`#SUP桨板` 与 `#桨板` 重复覆盖同一搜索意图，中文用户搜"SUP桨板"的量远小于"桨板"。建议替换为扩品类的标签如 `#户外运动`。

## 封面字约束（2026-06-04 新增）

封面字出现在视频流中的展示时间<1秒。约束：

- **优先 10-15 字**，上限 20 字。超长句在缩略图中缩小到看不清
- **一句话说一个钩子**，不写两句话。"三个没玩过水的朋友。半小时后，没人想上岸。" → 只取后半句
- **不写冒号后面的步骤**。"零基础的第一块桨板：跪上去，慢慢起，看远处" → 封面写前半或拆两行
- **不用万能句式**。"和你想象的不一样"换成具体的反差描述
