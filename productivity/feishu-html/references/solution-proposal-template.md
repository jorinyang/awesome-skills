# B2B Solution Proposal Page Template

适用场景：技术方案/系统建设方案/项目提案的客户演示页面。

## 页面结构

```
┌─ Nav（固定导航，锚点跳转）
├─ Hero（项目名称 + 4个核心数据指标卡）
├─ 功能架构（前台/后台分组卡片 grid）
├─ 信息权限分层（3列递进式卡片，彩色顶部边框）
├─ 业务流程（横向步骤流 flow-step + arrow）
├─ 技术架构（分层架构图 arch-layer）
├─ 费用方案（双卡对比 price-grid，推荐方案加边框高亮）
├─ 实施周期（时间线 timeline）
├─ 交付物清单（3列卡片）
├─ 维护说明（表格）
├─ CTA 联系区（深色背景 + 白色按钮）
└─ Footer
```

## 设计规范

- **配色**：商务蓝 `#1a56db` 为主色，避免渐变/花哨效果
- **排版**：信息密度适中，留白充足，层级清晰
- **卡片**：圆角 12px，hover 微上浮 + 阴影
- **表格**：蓝色表头，hover 行高亮
- **响应式**：mobile 隐藏导航链接、流程步骤纵向排列、价格卡全宽

## 双轨交付模式

当用户要求「创建飞书文档 + 生成HTML」时：
1. 先用 `feishu-doc` 技能创建内部版飞书文档（完整方案，含费用/排期）
2. 再用本模板生成客户演示HTML（聚焦功能/价值/流程，弱化内部管理信息）
3. HTML 中 CTA 按钮链接到微信/飞书等实际联系方式

## 关键区别：内部版 vs 客户版

| 维度 | 飞书文档（内部版） | HTML（客户版） |
|------|-------------------|---------------|
| 费用明细 | ✅ 完整列出 | ✅ 双方案对比卡片 |
| 技术细节 | ✅ 数据库/API设计 | ❌ 仅展示架构概览 |
| 人员分工 | ✅ | ❌ |
| 流程图 | Mermaid（飞书渲染） | HTML/CSS 步骤流 |
| 信息权限 | 文字描述 | 可视化三层递进卡 |
| 交付物 | 列表 | 卡片展示 |
