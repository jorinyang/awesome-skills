# 写作声音增强层

本技能是 `humanizer` 和 `zhike-content-output` 的认知哲学增强层，注入 ljg-writes 的最高法则和语言铁律。当 humanizer 被加载时，本技能应同时加载。

## 最高法则：你会这样跟聪明的朋友说话吗？

这条覆盖一切。任何时候写东西，默念：**你会这样跟一个聪明的朋友说话吗？** 不会 → 改到会。

心里放一个具体的人，写给他，不写给"读者们"。

## 具体标准

### 诚实度
- **先亮自己的弯路，再给方向**——说服力来自你先错过，不是来自你说得对
- **不确定就说不确定**。"大概 70%"比"可能"诚实
- **不借势**：不用群体代言（"程序员都知道""业内人士都认为"），不编造经历，不用元评论（"接下来我们讨论"）

### 不自标深度
禁用以下宣告式语句：
- ✗ "再深入一层"
- ✗ "最深的一层是"
- ✗ "更深地说"
- ✗ "让我们进一步探讨"

深入是思考行为本身——下一句的内容让读者自己感到"原来不止这样"。说"我要深入了"反而把深入戳破了。

### 语言铁律

**词汇级**：
- 能两个字说的不用四个字。"进行讨论"→"聊"，"实现功能"→"做到"，"做出选择"→"选"
- 每个动词是一次判断。"放""搁""摆"不是一回事
- 砍：机械连词（"此外""另外"）、形容词通胀（"非常重要的关键"→"关键"）、软化词（"某种程度上""值得注意的是"）

**句式级**：
- 翻译腔免疫：这句翻回英文再翻回中文，还是原样吗？是→八成翻译腔，重写
- 同一种句式全文最多一次
- 被动句："被这事困扰"→"这事缠着"
- 长定语："那个由X引起的Y"→拆两句

**节奏级**：
- 短句多。介词砍。"通过/借/凭/在X上"→能不用就不用
- 计算机体系是母语。缓存、调度、编译、虚址——需要时用，像呼吸，不像引用

### 磨——写完后的检查

1. **口语检验**：逐段读。你会这样跟聪明朋友说吗？不会→改
2. **AI痕迹过滤**：拐杖词、宣传腔、夸大象征（"标志着""见证了""充满活力"）全删
3. **反风格**：
   - 在解释？→换一个看得见的场景
   - 在罗列？→砍到只留最狠的一个
   - 在全面覆盖？→一篇只说一个点
   - 同一论点出现两次？→改第一次，删第二次
   - 任何助手都写得出的句子？→改或删
4. **意外检验**：写这篇时你发现了什么自己之前没想到的？有→它在文中够显眼吗？没有→回去切得不够狠

## 加载规则

### 触发场景矩阵

#### 技术写作
| 场景 | 触发信号 | 示例 |
|------|---------|------|
| 技术博客 | 用户写/润色技术文章 | "帮我看看这篇技术博客有没有AI味" |
| 文档/README | 用户写项目文档 | "把这份README改得像人写的" |
| PR/MR描述 | 用户写代码提交说明 | "这个PR描述太机械了，润色一下" |
| 发布说明 | 用户写Release Notes | "changelog写得太官方了" |
| 内部wiki | 用户写内部知识文档 | "这篇on-call手册读起来太像GPT写的" |

#### 商业写作
| 场景 | 触发信号 | 示例 |
|------|---------|------|
| 商业提案 | 用户写方案/提案 | "这个提案读起来像模板" |
| 营销文案 | 用户写广告/推广文案 | "这篇推广文案太宣传腔了" |
| 邮件/通讯 | 用户写正式邮件或newsletter | "这封全员邮件太官腔了" |
| 品牌文案 | 用户写品牌相关文字 | "这个品牌故事不够真诚" |
| 演讲稿 | 用户准备演讲稿/分享稿 | "这个演讲稿像在念稿" |

#### 创意写作
| 场景 | 触发信号 | 示例 |
|------|---------|------|
| 文章/随笔 | 用户写个人文章 | "这篇文章读起来没有我自己的声音" |
| 社交媒体 | 用户写社交媒体帖子 | "这条推文太像AI写的了" |
| 反思/复盘 | 用户写个人反思 | "这个复盘读起来像工作报告" |
| 故事/叙事 | 用户写故事性内容 | "这个故事没有温度" |

### 自动伴随加载（与以下技能同时加载）

| 系统技能 | 触发条件 | 本技能角色 |
|---------|---------|-----------|
| `humanizer` | 用户说"去AI味/润色/改得像人写的" | 提供深层写作哲学——不只是清AI痕迹，而是建立人的声音 |
| `zhike-content-output` | 用户说"产出文档/对客文案" | 提供通用写作标准——业务铁律之上加通用语言铁律 |
| `editorial-review-prose` | 用户说"审一下文案/文本审查" | 在审查框架中注入"你会这样跟聪明朋友说话吗"的最终判据 |

### 手动触发关键词
写作声音、写作哲学、去AI味、润色、像人写的、有温度、真诚、不装、说人话、有自己的声音、不要太官腔、不要太宣传腔、不要太AI

### 不触发
- 纯技术输出（代码、配置、脚本）→ 不需要写作声音
- 结构化数据输出（JSON、表格、数据库查询结果）→ 不需要
- 用户明确要求正式/学术/官方语气时 → 不强行注入口语化

## 反翻译腔自查

每段写完扫一遍（信号词出现→整句重写）：

| 翻译腔 | 真实中文 |
|--------|---------|
| 我接住你 | 我在 |
| 提供支持 | 撑你 |
| 在情感上X | 情感上X（省"在"） |
| 这是必要的 | 必须这样；非这样不可 |
| 做出选择/做出决定 | 选；决定 |
| 在这个意义上 | 这么说 |
| 拥有...的能力 | 能... |
| 进行（研究/讨论/对话） | 直接用具体动词 |
| 通过X抓到Y | X动词直接带宾 |
| 一是...二是...三是... | 散文式排开，不编号 |
