# 题库 MD↔JSON 同构维护（升级 / 重建 / 删改题）

适用：已有「题库 MD + `_practice_bank.json`（+ `_build.js` 内联 HTML 练习系统）」双工件，需要删题/加题/改模块分布/升版本时（本案例：OPT 认知培训题库 v0.1→v0.2，删 M6 14 题、M2/M4 各 +7）。

## 关键约定（先读源文件，再动手）

1. **JSON 是单一事实源**，MD 由 JSON 程序化生成（同构）。改题只改 JSON，再重新生成 MD。`_build.js` 会把 JSON 内联进在线练习 HTML——JSON 定稿后记得重跑 `node _build.js` 重建练习系统。
2. **JSON schema**：`{"meta":{title,version,count},"questions":[{"id","type":"single|multi|judge","module":"M1".."M5","question","options"|[null],"answer","analysis"}]}`，id 从 1 连续。
3. **judge 题题干不带 "（　　）"**：JSON 的 question 文本以"。"结尾，MD 生成层再追加"（　　）"。新题若在题干里自带占位符，会产出"（　　）（　　）"双空格。
4. **答案区两种格式并存**（解析器必须兼容两种）：
   - 练习 MD：`**N. 答案：X**｜所属模块：M1`（同行）+ 下一行 `解析：…`
   - 正式 MD：`**N. 答案：X**` + 下一行 `解析：…` + 单独一行 `**所属模块：M1（个人 AI Native 三层）**`
5. **模块值可能含空格**（"M1（个人 AI Native 三层）"）——正则取模块用 `(.+?)`，不要用 `\S+`。
6. **编号体系不同**：练习 MD 全局 1..80 连续；正式 MD 按题型分段编号（单选 1..13 / 多选 1..4 / 判断 1..8）。解析器必须按 (题型, 题号) 作 key，否则跨题型 id 互相覆盖。

## 转换脚本结构

- 加载 JSON → 过滤/插入 → 按 (type 顺序 single<multi<judge, module 顺序, 组内原序) 排序 → 重编号 → 写 JSON → 由 JSON 生成 MD（`open(..., newline='\r\n')` 保持仓库 CRLF 习惯）。
- **PITFALL 原地覆盖**：转换脚本读入源 JSON 又写回同一路径，中途崩溃会把 v0.1 覆盖成半成品 v0.2，且重跑会双重转换（assert 失败）。
  - 对策 a：先写临时文件/先备份；
  - 对策 b：源被破坏时用**未被改动的 MD 镜像反解析恢复**（MD↔JSON 同构可逆：MD 题干+选项区 + 答案区解析出完整 JSON）。本次即用此法恢复。

## 校验必须独立于生成

生成脚本内的自校验用同一份内存数据，发现不了生成器自身 bug（本次 judge 题干带（　　）就是生成器自检全绿、独立校验才暴露）。交付前用**独立校验脚本重新解析两个 MD 文件 + JSON**，五项全过才算完成：

1. `json.loads` 通过；
2. 题数 / id 连续 / 模块分布达标（对照目标表）；
3. 答案-选项位置对应：answer 字母 ⊆ 选项数范围（single 恰 1 个、multi ≥2 个）、judge 必须 options=null 且 answer∈{√,×}、每题选项均以 `A. ` 前缀开头；
4. **跨题库零重复**：normalize（去空白、去"（　　）"）后比对题干全文；两个库都定稿后再跑一次——本次练习 #21 与正式 #6 题干撞车（两库新题同场景同问法，仅选项不同）直到最终校验才发现；
5. **黑名单 grep**：硬词（如"三本账/双清单/三不接/T1 四维/分轨工作法/服务边界与角色工作法"）0 命中，**修订说明行豁免**；部分词有合法语境（如"责任边界"在 M2 五层封装层名里合法），需输出出现位置人工核对，而不是一刀切报错。

## 模块口径变更（删模块/重分配题型时）

- 用户给"删 X 题、换 Y 题、目标分布"时，先核对实际文件里的模块标注与覆盖对照表（"以实际文件为准"）；若用户列举的题号与实际标注冲突，选能同时满足「删题数=新增数」和「目标分布」的解释执行，重分类的题（如 T1 升格评估 M6→M5）在修订说明中写明。
- 新题必须逐条覆盖用户点名的考核点清单（如 M2 三误区/可检验标志定层/岗位边界先动），并保持情景题占比（约 40%）；题型配比允许微调（本次 45/15/20 → 50/12/18），同步更新 MD 头部计数。

## 本机工具坑（Windows + 中文路径 + CRLF）

- `read_file` 对 CRLF/混合 EOL 的 UTF-8 中文文件报 "Binary file - cannot display" → 改用 terminal `sed -n 'a,bp' 文件` / `grep` 读。
- `search_files`（rg 后端）对含中文的路径报 IO error → 用 terminal `cd 目录 && grep -n ...`。
- 校验脚本里解析 MD 时按 `splitlines()` 处理，天然兼容 CRLF。
